# Reliable Python 0.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Reliable Python 0.4.0 and refresh the organization marketplace with the released plugin contents.

**Architecture:** Freeze the tested `develop` tree, merge it into `main` with the repository's documented non-fast-forward release topology, tag that `main` commit, and publish release notes from the `v0.3.1..v0.4.0` diff. Then update the marketplace's vendored Git subtree from released `main`, align its catalog copy, validate the vendored plugin, and publish marketplace `main`.

**Tech Stack:** Git, GitHub CLI, Git subtree, Python `unittest`, bundled AST auditor, Claude plugin validator

**Spec:** `docs/superpowers/specs/2026-09-14-python-solid-checks-design.md`; release mechanics are defined by `CONTRIBUTING.md`

## Global Constraints

- Release version is exactly `0.4.0`, tagged as annotated tag `v0.4.0` on `main`.
- `main` and `develop` must have identical trees immediately after the release merge.
- The plugin remains dependency-free and supports Python 3.10 or later.
- `SOLID01` through `SOLID05` are review guidance; only conservative same-module `SOLID03` substitution cases are static findings.
- `SOLID*` findings remain advisory and cannot block the Stop hook.
- `PY001` and `PY004` are static warnings; `PY002`, `PY003`, and `PY005` remain guidance-only.
- Preserve the user's untracked `.claude/` directory and all unrelated working-tree content.
- Do not tag or publish until the full test, audit, manifest, and plugin-validation suite passes.

### Task 2: Publish Reliable Python 0.4.0

**Files:**
- Merge: the complete `develop` tree into `main`
- Create remotely: annotated tag `v0.4.0`
- Create remotely: GitHub Release `v0.4.0`

**Interfaces:**
- Consumes: the validated tree from Task 1
- Produces: public `main`, `develop`, tag, and GitHub Release for 0.4.0

- [ ] **Step 1: Confirm the release diff and generate evidence-based notes**

```sh
git diff --stat v0.3.1..develop
git log --reverse --format='%h %s' v0.3.1..develop
```

Expected: the diff includes the SOLID skills and checks, Python-practice skill and checks, Stop-hook advisory behavior, documentation, manifests, and tests.

- [ ] **Step 2: Merge the frozen tree into production**

```sh
git switch main
git merge --no-ff develop -m "Merge develop into main"
git diff --exit-code main^{tree} develop^{tree}
```

Expected: a merge commit is created on `main`, and the two trees are identical.

- [ ] **Step 3: Tag the production commit**

```sh
git tag -a v0.4.0 -m "v0.4.0"
git merge-base --is-ancestor v0.4.0 main
```

Expected: the annotated tag resolves to the new merge commit and is reachable from `main`.

- [ ] **Step 4: Publish branches and tag atomically**

```sh
git push --atomic origin develop main v0.4.0
```

Expected: all three refs update, or none do.

- [ ] **Step 5: Publish the GitHub Release**

```sh
gh release create v0.4.0 --repo reliable-coding-agents/reliable-python --title "v0.4.0" --target main --notes-file /tmp/reliable-python-v0.4.0-notes.md
```

The notes file must contain exactly:

```markdown
## Summary

Reliable Python 0.4.0 adds conservative Python SOLID review and explicit Python practice guidance alongside the existing Power of Ten profile, code-smell review, and NumPy-default docstring checks.

## New Features

- Adds `applying-solid-principles`, an evidence-based review skill covering all five SOLID principles in Python.
- Adds advisory `SOLID01`–`SOLID05` findings, with high-confidence same-module static checks for `SOLID03` substitution risks: disabled concrete methods, method/property changes, sync/async changes, and signatures that reject calls accepted by a local base class.
- Adds `writing-maintainable-python` guidance for import-safe entry points, explicit `main()` assembly, focused functions, public annotations, and readable comprehensions.
- Adds `PY001` for bare module-body calls and `PY004` for missing public function annotations. `PY002`, `PY003`, and `PY005` remain guidance-only.

## Behavior

- SOLID findings remain visible in direct audits but do not block the Stop hook.
- Python-practice warnings use the existing changed-scope reporting and gate configuration.
- Static substitution checks stay deliberately local and conservative; the auditor does not import code, infer types, or claim to verify semantic invariants.

## Upgrading

Refresh the `reliable-coding-agents` marketplace in Codex or Claude Code, then reinstall or update `reliable-python` to 0.4.0.
```

Expected: the GitHub Release is public and targets tag `v0.4.0` from `main`.
